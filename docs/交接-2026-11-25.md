## 六、几条踩过的规矩（贴在墙上）

1. **两套算法算同一个 key，迟早分叉** → 让算 key 的那一端把结果传下去。
2. **测试桩比现实善良** → 桩要照着真实 API 的"缺陷"来造（OfflineAudioContext 没有 close）。
3. **检查脚本不能吞 stderr** → 只看退出码会把"语法错误"当成通过。
4. **静默失效最难查** → 权限缺失、钩子没注入、key 不匹配，全都"不报错"。每个都要有专门的断言。
5. **先取证再改** → 今天 5 个"疑难杂症"里有 4 个是靠 bridge 现场读 DOM / 抓包解决的，猜基本都猜错。
