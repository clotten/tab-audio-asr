## 二、今天的错误（按"代价"排序）

### 1. 字幕库一直是空的 —— 一条消息参数没转发（代价最大）

`popup` 算好了 `videoKey` 传上来，`background.js` 转发给 offscreen 时**只转了 `url`**：

```js
callOffscreenTask({ type: 'INGEST_URL', url: msg.url })   // ← videoKey 被丢了
```

offscreen 里 `if (videoKey)` 为假 → 静默不入库。**提取了一堆视频，库里一个字幕都没有。**

两个教训：
- **静默失败比报错更难查**。当时应该 `else` 记一条 `diag.libraryError`，一眼就能看出"没 key"。
- **转发层是参数丢失的重灾区**。凡是"经过三层（popup → SW → offscreen）"的字段，都要在测试里断言它到达了最后一层。

修好之后我在仿真里加了断言：`入库的 key 带时长`——如果 key 中途丢了，这条会红。

### 2. 同一类 bug 犯了三次：某个分支"忘了按模式走"

- 映射分支写了 `session.diag?.source === 'url'`，绕过了统一的 `isStaticTranscript()` → 不高亮；
- 重绘判据 `sig` 只比句数和末句字数 → 换会话时句数相同就**沿用旧行**；
- ticker 的"已停止"分支漏了按模式选择滚动目标 → 静态稿一滚动就**跳回末尾**。

根因都一样：**同一个判断散落在多处，改的时候漏一处**。
现在的对策：所有模式差异集中在 `MODES` 注册表（`mapping / statusLabel / followLabel / scrollTarget / sig`），
再加两条**源码级不变式**（`simulate-panel.mjs` 场景 11）：按模式判断的地方 ≥4 处、禁止裸写 `if (...) scrollToBottom();`。

### 3. 改安全策略会打掉"本来能跑"的写法

为了跑 wasm 加了 `script-src 'self' 'wasm-unsafe-eval'`，于是自测页的内联 `<script>` 被 CSP 拦掉——只有真点开那个页面才会发现。
现在有 `tools/lint-csp.mjs`：禁内联脚本、禁 `on*=` 属性、并**反向守卫**"不允许放宽到 unsafe-inline"。

### 4. 改错文件 / 改错行（机械性错误，但浪费最多时间）

今天至少有 6 次：
- 把 CSS 追加到了 `.js` 末尾（CSS 其实在 `build()` 的模板字符串里）；
- 用 PowerShell 字符串替换时，`${...}` 和反引号被 PowerShell 抢先解释，把代码写坏；
- 按行号替换时行号算错，把 `renderProgress` 的变量改成 `note()` 的；
- 用"页面上的文字"（`>字幕库<`）当定位锚点，结果匹配到了刚加的**标签按钮**，误删了整个 `<nav>`。

对策：**改 HTML 用整文件重写（write），改 JS 先 `node --check`**，替换一律带唯一上下文而不是裸关键词。
今天每次 `node --check` 都抓到了问题——这步不能省。

### 5. 用"看起来对"的兜底掩盖问题

静态稿找不到"当前句"时，我写的是 `else scrollToBottom()`——一句"没有就算了"的兜底，
结果是**每帧都跳回全文末尾**。正确的兜底是"停在前面最近的一句"。

教训：**兜底逻辑也要有语义**。"随便做点什么"通常比"什么都不做"更糟。

## 三、方法上确实有效的

1. **先验证再实现**：Silero 先用 Python 在真音频上跑（音乐 0.003 / 讲话 0.53）才决定打包 15.9MB。
2. **真·实时回放**（`replay-live.mjs`，1 倍速 + 真模型 + 真接口）——只有它能暴露"预览抢请求配额把定稿拖到 4.6 秒"这种问题。6 倍速仿真永远看不出来。
3. **拿数据定参数**：`targetMinMs` 800→2000 是"碎片率 30%→0%"这个数字定的，不是拍脑袋。
4. **源码级不变式**：有些 bug 用运行时测试抓不到（比如"某分支忘了按模式走"），只能扫源码。
5. **修改即验证**：每个小步都跑 `node --check` + 相关测试，今天 14 套检查抓到了几乎所有回归。

## 四、明天的第一件事（字幕库）

已修的部分：`background.js` 现在会把 `videoKey` 一起转发；offscreen 在拿不到 key 时**用媒体地址兜底**而不是静默跳过；入库失败会写 `diag.libraryError / librarySaved / libraryKey`。

**你要验的**：

1. 刷新扩展 → 在某个视频上点「整段提取」
2. 跑完后切到「字幕库」标签，下拉里应该有一条记录（标题 · 句数 · 日期）
3. 打开**同一个**视频，面板应自动命中、秒出、不再发请求

**如果还是空的**，有两个信息最有用（都在 `chrome.storage.local.asrSession.diag` 里）：

- `librarySaved` 是 `false` 还是 `undefined`（undefined = `waitSaveDoc` 根本没跑，说明 code 没生效）
- `libraryError` 的具体文本

`diag.libraryKey` 顺便能看出 key 算成了什么——如果它没有 `#时长` 后缀，说明 `videoKeyOf` 没拿到 `duration`（`<video>` 还没加载完就点了提取）。

## 五、还没做但值得做的

1. **跨段合并**：某段不以 `。！？` 结尾且下一段 1.5 秒内开始 → 合并后重新定稿。治 `本部。` 这类"被气口切断"的错，纯语法规则。
2. **字幕库的去重与合并**：同一视频提取两次会覆盖（现在的行为），但如果第二次提取不完整（被取消），会把完整的覆盖成残缺的——应该"更长的优先"。
3. **取消后的续跑**：现在取消会把已转的句子留下，但没有"继续上次"的入口。
4. **直链 + HLS/DASH**：现在只支持直链 mp4；m3u8/mpd 的站（B 站、YouTube）还不支持。
