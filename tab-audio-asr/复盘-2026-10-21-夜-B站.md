# 复盘：2026-10-21 夜 · B 站换集之战

> 白天写完了功能，晚上全花在**一个 bug** 上：换视频后提取的还是上一个视频的音频。
> 这一晚最大的收获不是修好了，而是学会了**怎么证明自己在修什么**。

---

## 一、结论（先说结果）

B 站、以及任何用 MSE + `blob:` 的站点，提取音轨的可靠路径是：

```
location.pathname 里的 BV 号
  → api.bilibili.com/x/web-interface/view  → cid
  → api.bilibili.com/x/player/playurl      → dash.audio[最高码率].baseUrl
```

日志实测（用户提供）：

```
v2026-10-21c
探测完成 · 平台=bilibili · 模式=mse · 分片=2 · 选用ID=42780986019 · 类型=bilibili-api
整段提取 · 即将下载ID=42780986019
```

探测与提取 ID 一致、换视频 ID 跟着变 → 通了。

---

## 二、走过的四条死路（都要记住，别再走）

### 1. `window.__playinfo__` —— 首屏快照，永不更新

一开始用它，第一个视频能用，换集就锁死在第一个。
实测：`location.href` 换成 `BV1fxni6XEwD`，`__playinfo__` 里的 `baseUrl` 还是原来那个。

### 2. `window.__INITIAL_STATE__` —— 也是快照，而且是**另一个**视频的

同一时刻三个值互不相同：

| 来源 | 指向 |
|---|---|
`__playinfo__` | `42906225680` |
`__INITIAL_STATE__` | `42868804351` |
`location.href` | `BV1fxni6XEwD`（真实） |

**页面上任何"全局变量"都可能是某个历史时刻的残影。**

### 3. 挂钩 `playurl` 请求 —— 思路对，但两个坑

- `executeScript({world:'MAIN', files:[...]})` 在这台 Edge 上**静默不生效**（`window.__dshAsrHookInstalled` 永远是 `undefined`）；换成 `world:'MAIN', func` 才行。**平台陷阱，记下来。**
- 就算挂上了，**用户没按播放就没有新请求**。换集后不播，钩子抓不到东西。

### 4. "取分片里最近的那个" —— 直觉是错的

`performance` 里旧视频的分片**比当前视频的更"新"**（startTime 68956 vs 14652）。
按"最近"取会取到旧视频；按"体积最小"这次侥幸对了，但换两个视频就不一定。

**只有按 ID 对齐才可靠。**

---

## 三、最该记住的一条原则

> **静默回退到旧数据，比直接失败糟糕得多。**

中间版本里，`PICK_MEDIA` 失败会回退到 `__playinfo__`，于是"每次都成功，每次都转同一个视频"。
用户看不出错，只觉得"怎么又是上一个"——这种 bug 的排查成本远高于一个 403。

现在代码里写死了：**有分片地址却挑不出音轨时直接失败，绝不回退到快照。**

## 四、我这晚犯的机械错误（都是自己造成的）

| 错误 | 表现 | 现在的防线 |
|---|---|---|
**先用后声明**（TDZ） | `Cannot access 'url' before initialization` | 每步 `node --check`；逐段复核声明顺序 |
**函数签名不匹配** | `sendResponse is not defined` | 新增 `tools/check-sendresponse.mjs`：用 `sendResponse` 就必须在 `onMessage` 签名里声明 |
**代码插错位置** | CSS 追加到 `.js` 末尾、代码插进注释里、`}` 配对错 | 大改一律 `write` 整文件；小改用行号+上下文，改完立刻 `node --check` |
**PowerShell 转义** | `${}`、反引号、`\\n` 被 PowerShell 先解释 | 复杂片段先写成临时文件再 splice；正则改用 `startsWith` 这类无转义写法 |
**BOM** | `manifest.json` 带 BOM → `JSON.parse` 直接失败，扩展装不上 | `tools/strip-bom.mjs`，每次提交前跑 |

一句话：**改完必验**。这一晚 `node --check` 抓到了绝大多数，剩下两个是它抓不到的（TDZ、签名），所以各自补了检查。

## 五、浏览器桥（Kimi WebBridge）的用法与边界

用对了非常值——这一晚所有关键结论都是它给的现场数据。

**用法**

```
POST http://127.0.0.1:10086/command
body: {"action":"evaluate","args":{"code":"..."},"session":"<任务名>"}
```

- JSON 必须写进**无 BOM 的临时文件**再 `--data-binary`（PowerShell 直接拼会坏）
- 常用action：`list_browser_tabs` / `attach_tab` / `evaluate` / `network` / `navigate`

**边界（实测）**

- 读不到 DevTools 控制台历史（没有 console 接口）
- 不能 `navigate` 到 `chrome-extension://…`（`-32000 Not allowed`）
- 目标标签页里若有**扩展浮窗**（含我们自己的字幕面板），该标签页的操作会被整体拒绝
- `close_tab` 关的是"会话当前标签"——我因此误关了用户一个 B 站标签

## 六、成本教训（真金白银）

- 峰值时段试错花了 ¥4 还没拿到结果；`20 秒/段`意味着一集 26 分钟的视频 ≈ **80 次请求**。
- 已加：**超过 10 分钟的视频，第一次点「整段提取」只给估算、不执行**，要再点一次确认。
- 已确认：`401/403/404/400/413` **不重试**，只有 `429/5xx` 才退避。
- 待办：同一视频的音轨码率会变（`30280` ≈200kbps vs `30216` ≈67kbps），应在音轨里**优先挑 30280**，别用低码率去识别。

## 七、方法上真正有效的三件事

1. **先证明，再动手。** 这一晚四次推翻自己的假设（快照会更新、钩子装上了、取最近就对、分片能区分音视频），
   全靠现场数据：`performance` 时间戳、`HEAD` 的 `content-type`/`content-length`、`cid` 对比。
2. **让"是否生效"可观测。** 因为反复出现"改了没生效"，加了版本戳：
   - 控制台：`内容脚本已加载 v2026-10-21c`
   - DOM：`document.documentElement.dataset.dshAsrVersion`
   以后远程排查一行就能确认版本。
3. **把结论写进文件，不留在对话里。** 对话会被压缩，磁盘不会。这一晚的每条实测数字都落进了
   `开发笔记.md` / `待修-B站换集.md` / 本文件。
